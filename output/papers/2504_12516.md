## Benchmark Modalities

**Modality Types:** text

**Description:** The benchmark tasks consist of text-based questions paired with short-string text reference answers, which agents must solve by interacting with text and layout on the web.

## Analytical Tasks

**Task Types:** factual recall, open ended qa, logical and quantitative reasoning, causal and temporal reasoning, calibration and uncertainty, agentic tool use

**Detailed Description:** The benchmark tasks consist of open-ended QA requiring multi-hop factual recall of obscure information. Correctly answering requires persistent web navigation (agentic tool use) to parse complex logical and quantitative constraints (e.g., number of TV episodes) and temporal constraints (e.g., historical date ranges). Models are also evaluated on calibration and uncertainty by extracting a confidence score for their predictions.

## Summary

BrowseComp is a challenging benchmark comprising 1,266 fact-seeking questions designed to evaluate an AI agent's ability to persistently browse the web for hard-to-find information. The questions are structured as inverted constraint-satisfaction problems, making them extremely difficult to search for but easy to verify via short text reference answers.

## Key Findings

Standard LLMs perform poorly without specialized search loops, with GPT-4o achieving 0.6% and GPT-4.5 achieving 0.9% accuracy. Enabling basic web browsing for GPT-4o only yields 1.9% accuracy, while OpenAI o1 reaches 9.9% via stronger reasoning. OpenAI Deep Research, an agent designed for persistent browsing, achieves 51.5% accuracy, scaling smoothly with test-time compute. Parallel voting strategies (e.g., Best-of-N based on confidence) boost this accuracy by up to 25%.

**Answer Multiplicity:** single_answer

**Plurality Treatment:** noise

**Facets Explanation:** The reference answers were authored by contracted human trainers who constructed highly specific, multi-constraint questions around a target 'seed' fact to ensure a single, indisputable answer. Solving these questions inherently requires retrieving information from the open web, as the necessary knowledge is not contained within the prompt stimulus. Potential ambiguities or secondary valid answers discovered during cross-checking or post-hoc evaluation were treated as noise, resulting in either question revision or item exclusion to maintain a clean, single-answer key.
